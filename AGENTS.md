# Agent Instructions

## Commands

- There is no build step. The config is a set of tmux commands plus POSIX sh scripts.
- Isolated smoke test (never touch the user's real server): `tmux -f tmux.conf -L smoke new-session -d && tmux -L smoke list-keys >/dev/null && tmux -L smoke kill-server`
- **That smoke test does NOT catch a syntax error.** It passed on a config with `tmux.conf:369: syntax error` in it — `-f` reports parse errors to the attached client, and a detached `new-session -d` has none, so nothing reaches your shell. To actually check the config parses, `source-file` it into a running server, where errors go to the invoking client: `tmux -f /dev/null -L chk new-session -d && tmux -L chk source-file "$PWD/tmux.conf"; tmux -L chk kill-server`. On a machine without zsh it also prints `not a suitable shell: /bin/zsh`, which is environmental, not a config error.
- Lint every script: `sh -n scripts/*.sh bootstrap.sh` — and `bash -n shell/functions.sh` separately. `functions.sh` is sourced in bash/zsh and its zsh completion block is not valid POSIX sh, so it has never passed `sh -n`; linting it with `sh` reports a syntax error that is not one.
- **Check the docs match the keys: `./scripts/check-docs.sh`** — asserts every binding this config defines appears in both `README.md` and `scripts/keys.sh`. Run it after touching any key. It diffs against `tmux -f /dev/null`, so only what this config adds or overrides is checked.
- Reload the live config: `tmux source-file ~/.config/tmux/tmux.conf`
- Install / re-wire (idempotent; **fetches the plugin submodules**, `--no-plugins` skips that): `./bootstrap.sh`
- **Always** test on an isolated socket (`tmux -L smoke` / `-L pruebas`); never against the user's running server. **Use a fresh socket name for each run** — reusing one immediately after `kill-server` races and produces "server exited unexpectedly", which reads exactly like a config error and is not one.

## High-level architecture

- `tmux.conf` is the real, versioned config, auto-loaded because the repo lives at `~/.config/tmux`. There are no templates — tmux expands `~`/`$HOME` natively.
- `sessions/*.conf` are **sh fragments sourced by the shell functions** (`. dev.conf`) with `$SESS`/`$DIR` in scope — they are **not** loaded with `tmux source-file` (which does not expand shell variables). This keeps any `set-option -t` next to the `new-session`.
- **SSH shield (two layers)**: `scripts/session-created.sh` (the `session-created` hook) sets a per-session `default-command` for every `ssh_*` session, and `scripts/ssh-host.sh` is that command (host by argument; no host → local shell, never SSH). `default-command` is a **session option** → it applies to `new-window` AND `split-window` and never leaks to local sessions.
- `scripts/` are POSIX sh helpers: `theme.sh` (**the palette** — four Catppuccin flavours, the semantic roles, the measured pill inks, and the fuzzback popup colours), `agent.sh` (resolve the AI agent), `ssh-host.sh`, `split.sh` (split the longer axis), `session-color.sh` (pill colour: the accent for local sessions, a per-host tint for `ssh_*`), `session-created.sh` (SSH shield + publishes `@pill`; also the `session-renamed` hook), `session-strip.sh` (the CURRENT session's pill → `@session_strip`), `session-save.sh` (roster of open sessions, replayed by `t`), `palette.sh` (`Alt-Space` command palette), `keys.sh` (`prefix + ?` cheatsheet), `ask.sh` (Esc-cancellable prompt/confirm), `urls.sh` (URL picker), `promote.sh` (pane → session), `open-selection.sh` (copy-mode `C-o` → `$EDITOR`), `copy-last-output.sh` (`prefix + Y`), `fzf-style.sh` (sourced; the popup palette, read from the theme), `check-docs.sh` (a lint, not a runtime helper — see Commands).
- Two copy-mode features depend on things that fail SILENTLY, so both are scripts that report instead of pretending: `prefix + Y` needs the shell to emit **OSC 133** marks (tmux.1: without them `previous-prompt`/`next-prompt` "do nothing" — and the sequence then copies the PROMPT line while claiming success), and `C-o` must resolve `$EDITOR` at **runtime**, not at config-load time, because `run-shell` inherits the tmux server's environment. Anything selected in copy-mode is untrusted input into a shell command — quote it.
- **Plugins are git submodules under `plugins/`, and there is NO plugin manager.** The submodule SHA is the pin; `git submodule update --remote plugins/<name>` plus a commit is the upgrade. TPM was evaluated and rejected (its `#tag` pin only applies at install time, changing it is a no-op, `prefix + U` then fails on a detached HEAD, its last substantive commit was Feb 2023, and `brew install tpm` is unavailable on Linux). Five ship: `tmux-fingers`, `tmux-fuzzback`, `extrakto`, `tmux-open`, `tmux-easy-motion`. Each load in §5 is guarded so a clone without `--recurse-submodules` degrades instead of erroring; `tmux-fingers` is guarded on its **binary**, because its loader fires a network installer through `run-shell -b` during config parsing when the binary is missing — and it does that _before_ reading `@fingers-skip-wizard`, which only covers the version-mismatch path. The no-prefix `Alt-f` binding right below the load line repeats the same binary guard for a different reason: `@fingers-key` only ever binds relative to prefix (the plugin's own README says so), so `Alt-f` goes through the plugin's documented `@fingers-cli` global option instead — unguarded, a clone mid-fetch would bind `Alt-f` to an empty `#{@fingers-cli}` and silently no-op.
- `tmux.conf` §6 ends with `source-file -q` of the work and local layers. They are **last on purpose**: a `run-shell` completes before the next line is parsed, so those two files override this file and every plugin.
- `shell/functions.sh` defines `t` / `tp` (alias `tcwd`) / `tssh` / `tcopy` / `agent` plus the `ulimit` block; it is sourced from the rc by `bootstrap.sh`.
- **There is no numbered session jump any more** (`prefix + <digit>` for 1-9, and the `session-order.sh`/`session-goto.sh` pair behind it, were removed — do not reintroduce either as unused ceremony if a future round drops the feature that needs them again). Switching sessions without typing a name is `Alt-,` / `Alt-.` (prev/next), `Alt-s` (the `choose-tree` picker), `prefix + Tab` (last session), and `prefix + 0` (always `main`, unconditionally — see tmux.conf §2b). `choose-tree`'s own `-O` sort accepts only activity/creation/index/key/modifier/name/order/size/z (verified against tmux's source; `-O time` is not a valid name and errors) — it has no relationship to `main`-first-then-recency and never did; that comparison stopped mattering once there was nothing left to compare it to.
- **The palette lives in ONE place**: `scripts/theme.sh`. It publishes the 26 Catppuccin colours for the flavour in `@thm_flavor` (latte/frappe/macchiato/mocha, values from `catppuccin/palette` v1.8.0 — NOT from `catppuccin/tmux`, whose theme files ship `subtext_0`/`subtext_1` swapped), then the semantic roles (`@thm_accent`, `@thm_dim`, `@thm_ink`, `@thm_ssh_tints`…). `tmux.conf` reads them with `#{E:@thm_…}`; the scripts read the same options with `tmux display-message -p '#{E:@thm_…}'` and carry a hardcoded fallback only for a run outside tmux. Changing theme is `@thm_flavor` + a re-run — do not reintroduce hex anywhere else. **The pill inks are COMPUTED in awk, not listed**: white reads on Latte's blue and not on Mocha's, and inside Latte it reads on blue and not on yellow, so a hardcoded table would be 56 numbers to keep honest. Style options (`message-style`, `pane-border-style`, …) expand formats on tmux 3.4, verified on an isolated socket, so they can use `#{E:@thm_…}` too.
- The bar is `bg=terminal` — it paints no background, so it takes the terminal's, which is why a light flavour wants a light terminal and a dark one a dark terminal. Ratios quoted in comments are against the bar the flavour assumes (pure white for Latte, the flavour's own base for the dark three); the inks themselves are computed, so they follow whatever the palette says.
- Deviations from upstream `catppuccin/tmux`, all for legibility and all commented in place: on Latte the pill text is `#ffffff`, not `crust` (crust clears 4.5:1 on no Latte accent); inactive borders are `overlay2`, not `overlay0` (2.60:1 on white) or `overlay1` (3.20:1, too little headroom over the 3:1 floor once the border is `pane-border-lines heavy` instead of the thin default); `message-style` is white-on-accent, not upstream's 1.44:1 teal-on-overlay0.
- Every pill is the accent; only `ssh_<host>` sessions are tinted, from the `@thm_ssh_tints` cycle. Each entry carries its own ink (`bg:ink`) because Latte's accents span luminances — white is legible on mauve and illegible on yellow.
- Nothing on the bar uses `#()`. `@session_strip` is written by a hook and read back with `#{E:@…}`; per-window icons are a nested `#{?#{==:…}}` chain. A `#()` re-runs on the **`status-interval` timer**, not on every redraw (measured: 6 windows at `status-interval 5` = 6 forks per tick; ordinary redraws reuse the cache; `refresh-client -S` bypasses it). Since this config sets `status-interval 0`, a `#()` would run once and then be **stale forever** — that, not fork cost, is why the bar has none, and why no status module (battery/cpu/gitmux) can be added without turning the timer on and taking over `status-right`.
- Work config is layered at the end of `tmux.conf` via `source-file -q` of `~/.config/tmux-work/work.conf` (private repo) and `~/.config/tmux/local.conf` (per-machine, gitignored).
- Neovim interplay: `Alt-hjkl` are `is_vim`-guarded so smart-splits keeps working; nvim's clipboard/focus rely on `set-clipboard on` and `focus-events on`. See README.

## Key conventions

- **English everywhere**: Conventional Commits (subject + body; the body explains the _why_), comments, README, this file.
- POSIX `sh` with `set -u`; keep `sh -n` clean. No bashisms **except** `shell/functions.sh`, which is sourced in zsh/bash and may use `local` and `${var//…}`.
- In `tmux.conf`, `|` is **not** a pipe — every pipe must live inside `run-shell '…'`.
- **Write hex in LOWERCASE.** Inside a `#{?…}` conditional, or inside an option pulled in with `#{E:…}`, tmux still honours the legacy one-letter shorthands, so `#FFFFFF` loses its `#F` to the window-flags shorthand and renders `*FFFFF` — but `#ffffff` does not, because there is no `#f` shorthand. Lowercase (which is how Catppuccin publishes its palette anyway) removes the whole bug class; the `##FFFFFF` escape it used to need is no longer necessary. Commas inside a conditional still need `#,`.
- **Never bundle a tmux flag that takes an argument**: `set-option -tu <name>` parses as `-t u`, silently targeting a session called `u`. Write `-u -t <name>`.
- Anything from a session name is untrusted in a format: escape `#` → `##` before it reaches the status bar.
- The bar and the popups need a **UTF-8 locale**; with `LC_CTYPE=POSIX` tmux silently drops the Nerd Font glyphs (found while testing on an isolated socket).
- Always brace shell vars around multibyte characters (`"${i}·${s}"`) — `/bin/sh` on macOS is bash 3.2 and would read `$i·` as one variable name and trip `set -u`.
- SSH invariants: never `set -g default-command`; sessions are named `ssh_<host>`; document the escape routes by which a pane could still reach a local shell (explicit command, `join-pane`/`move-pane`).
- **A plugin may not own `default-command`, `status-interval` or `status-right`.** Those three are the SSH shield, the no-fork bar and the session strip. After adding or updating any plugin, assert on an isolated socket that `default-command` is still empty, `status-interval` is still `0`, and every `@thm_*` is still published. `tmux-sensible` fails the first (on macOS it runs `set -g default-command`), `catppuccin/tmux` fails the third (it opens with 37 `set -Ugq @thm_*`, unsetting the namespace `theme.sh` publishes), and every status module fails the second.
- **Check a plugin's key conflicts by key → COMMAND, never by which keys exist.** A plugin that steals a binding changes no key name, so a name-only diff reports nothing. `tmux-sessionist` silently replaced `prefix + C-Space` — the secondary leader — because its promote-window default `C-@` is the same keystroke as `C-Space`, and a name diff said "3 new keys, 0 lost". Diff `list-keys` output as `key<TAB>command` pairs against a run without the plugin.
- Plugin options do not reliably decline a binding: several plugins treat an empty option value as _unset_ and fall back to their default (`tmux-sessionist` does). Undo unwanted bindings after the load instead, and **rebind rather than unbind** anything that was already doing a job.
- The `ulimit` block only raises and caps at the hard limit (macOS soft `nofile` is 256, which crashes a multi-pane server).
- Keep the long explanatory comments, including the dead ends — they are why the config looks the way it does.
- Never push to `main` without the user verifying the phase on their Mac; develop on a branch.
