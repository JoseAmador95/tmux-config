# Agent Instructions

## Commands

- There is no build step. The config is a set of tmux commands plus POSIX sh scripts.
- **Safe config smoke test: `./scripts/check-docs.sh`.** It starts vanilla and candidate servers
  with `-f /dev/null` on fresh exact `-S` sockets, then explicitly `source-file`s tmux.conf so parse
  errors reach the invoking client and fail the check. A detached `tmux -f tmux.conf new-session`
  is not equivalent: it can lose parse errors because it has no attached client.
- The checker gives both servers a unique executable `SHELL` sentinel and gives the candidate a
  disposable HOME wired only to this checkout's tracked config. All XDG homes, `XDG_RUNTIME_DIR`
  and `TMUX_TMPDIR` are temporary too. Consequently it cannot load real work/local layers, replace
  the real session roster or reach the user's running server. Comparing the configured shell with
  the unique baseline proves the shared config leaves tmux's native `default-shell` selection
  unchanged even when the host's login shell is Zsh.
- Lint every script: `sh -n scripts/*.sh bootstrap.sh` — and `bash -n shell/functions.sh` separately. `functions.sh` is sourced in bash/zsh and its zsh completion block is not valid POSIX sh, so it has never passed `sh -n`; linting it with `sh` reports a syntax error that is not one.
- **Check the docs match the keys: `./scripts/check-docs.sh`** — sources the config into a fresh isolated server and compares effective `key<TAB>command` pairs against a second vanilla server. Every added or overridden binding must appear in both `README.md` and `scripts/keys.sh`; HOME, state and sockets are temporary.
- Full maintained validation: `./scripts/check-config.sh`. Read-only environment diagnosis: `./scripts/doctor.sh` or concise `./scripts/doctor.sh --brief`. CI runs both on Ubuntu 24.04 for pushes and pull requests.
- Reload the live config: `tmux source-file ~/.config/tmux/tmux.conf`
- Install / re-wire (idempotent; **fetches the plugin submodules**, `--no-plugins` skips that): `./bootstrap.sh`
- **Always** test with fresh exact `-S` sockets under a temporary directory; never against the
  user's running server. Reusing a socket immediately after `kill-server` races and produces
  "server exited unexpectedly", which reads exactly like a config error and is not one.

## High-level architecture

- `tmux.conf` is the real, versioned config, auto-loaded because the repo lives at `~/.config/tmux`. There are no templates — tmux expands `~`/`$HOME` natively.
- `sessions/*.conf` are **sh fragments sourced by the shell functions** (`. dev.conf`) with `$SESS`/`$DIR` in scope — they are **not** loaded with `tmux source-file` (which does not expand shell variables). This keeps any `set-option -t` next to the `new-session`.
- **SSH shield (two layers)**: `scripts/ssh-session.sh` validates one exact host, creates/adopts `ssh_*`, and stores the unsanitized target in session-scoped `@ssh_host`; `scripts/session-created.sh` sets the session's `default-command`, and `scripts/ssh-host.sh` executes it (no host → local shell, never SSH). Only `[A-Za-z0-9._@-]` is accepted and a leading `-` is rejected. The display-safe session name may be lossy; `@ssh_host` is authoritative and collisions fail. `default-command` is a **session option** → it applies to `new-window` AND `split-window` and never leaks to local sessions.
- `scripts/` are POSIX sh helpers: `theme.sh` (**the palette** — four Catppuccin flavours, semantic focus/urgent/attention/activity/current-search roles, their measured inks, colour-typed clock/pane-selector options, existing-session pill refresh, and the fuzzback popup colours), `agent.sh` (resolve the AI agent), `ssh-session.sh` / `ssh-host.sh`, `split.sh` (all split modes plus the shared `@no_split` guard), `toggle-log.sh` (safe per-pane logging), `session-color.sh` (pill colour), `session-created.sh` (SSH shield + publishes `@pill`), `session-save.sh` (roster with explicit `@layout`), `palette.sh`, `keys.sh`, `ask.sh`, `urls.sh`, `promote.sh`, `open-selection.sh` (system opener or runtime editor), `copy-last-output.sh`, `fzf-style.sh`, `doctor.sh`, `check-config.sh`, and `check-docs.sh`.
- Two copy-mode features depend on things that fail SILENTLY, so both are scripts that report instead of pretending: `prefix + Y` needs the shell to emit **OSC 133** marks (tmux.1: without them `previous-prompt`/`next-prompt` "do nothing" — and the sequence then copies the PROMPT line while claiming success), and `C-o` must resolve `$EDITOR` at **runtime**, not at config-load time, because `run-shell` inherits the tmux server's environment. `o` uses the same helper with a system opener and keeps tmux's `other-end` default when none exists. Anything selected in copy-mode is untrusted input into a shell command — quote it.
- **Plugins are git submodules under `plugins/`, and there is NO plugin manager.** The submodule SHA is the pin; `git submodule update --remote plugins/<name>` plus a commit is the upgrade. TPM was evaluated and rejected (its `#tag` pin only applies at install time, changing it is a no-op, `prefix + U` then fails on a detached HEAD, its last substantive commit was Feb 2023, and `brew install tpm` is unavailable on Linux). Four ship: `tmux-fingers`, `tmux-fuzzback`, `extrakto`, `tmux-easy-motion`. Each load in §5 is guarded so a clone without `--recurse-submodules` degrades instead of erroring. `tmux-fingers` is guarded on its **binary**, because its loader fires a network installer through `run-shell -b` during config parsing before reading `@fingers-skip-wizard`. Its automatic bindings are disabled; the config owns only guarded `prefix + f` and `Alt-f`, restoring `find-window`/unbinding `Alt-f` when the binary is absent.
- `tmux.conf` §6 ends with `source-file -q` of the work and local layers. They are **last on purpose**: a `run-shell` completes before the next line is parsed, so those two files override this file and every plugin.
- `shell/functions.sh` defines `t` / `tp` (alias `tcwd`) / `tssh` / `tcopy` / `agent` plus the `ulimit` block; it is sourced from the rc by `bootstrap.sh`.
- **There is no numbered session jump any more** (`prefix + <digit>` for 1-9, and the `session-order.sh`/`session-goto.sh` pair behind it, were removed — do not reintroduce either as unused ceremony if a future round drops the feature that needs them again). Switching sessions without typing a name is `Alt-,` / `Alt-.` (prev/next), `Alt-s` (the `choose-tree` picker), `prefix + Tab` (last session), and `prefix + 0` (always `main`, unconditionally — see tmux.conf §2b). `choose-tree`'s own `-O` sort accepts only activity/creation/index/key/modifier/name/order/size/z (verified against tmux's source; `-O time` is not a valid name and errors) — it has no relationship to `main`-first-then-recency and never did; that comparison stopped mattering once there was nothing left to compare it to.
- **The palette lives in ONE place**: `scripts/theme.sh`. It publishes the 26 Catppuccin colours for the flavour in `@thm_flavor` (latte/frappe/macchiato/mocha, values from `catppuccin/palette` v1.8.0 — NOT from `catppuccin/tmux`, whose theme files ship `subtext_0`/`subtext_1` swapped), then semantic blue focus, red urgent, yellow attention, green activity, and mauve current-search roles plus their inks and `@thm_ssh_tints`. `tmux.conf` reads them with `#{E:@thm_…}`; the scripts read the same options with `tmux display-message -p '#{E:@thm_…}'` and carry a hardcoded fallback only for a run outside tmux. Changing theme is `@thm_flavor` + a re-run — do not reintroduce hex anywhere else. The re-run refreshes live style formats, rewrites the colour-typed clock and pane-selector options, and recalculates the materialised session-scoped `@pill`/`@pill_ink` values for every existing session. **The coloured-background inks are COMPUTED in awk, not listed**: white reads on Latte's blue and not on Mocha's, and inside Latte it reads on blue and not on yellow, so a hardcoded table would be 56 numbers to keep honest. Style options (`message-style`, `pane-border-style`, …) expand formats on tmux 3.4, verified on an isolated socket, so they can use `#{E:@thm_…}` too.
- The tmux floor remains **3.4**. Automatic light/dark hooks, compact copy-position styling, and modal copy/view scrollbars are guarded at **3.6**; the tree-preview accent is guarded at **3.7**. On 3.4/3.5 the theme remains manually selectable, copy mode keeps tmux's default position UI with no scrollbar, and the tree works with its default preview style. Keep every newer option inside its parse-time version guard.
- The bar is `bg=terminal` — it paints no background, so it takes the terminal's, which is why a light flavour wants a light terminal and a dark one a dark terminal. Ratios quoted in comments are against the bar the flavour assumes (pure white for Latte, the flavour's own base for the dark three); the inks themselves are computed, so they follow whatever the palette says.
- Deviations from upstream `catppuccin/tmux`, all for legibility and all commented in place: on Latte the pill text is `#ffffff`, not `crust` (crust clears 4.5:1 on no Latte accent); inactive borders are `overlay2`, not `overlay0` (2.60:1 on white) or `overlay1` (3.20:1, too little headroom over the 3:1 floor once the border is `pane-border-lines heavy` instead of the thin default); `message-style` is white-on-accent, not upstream's 1.44:1 teal-on-overlay0.
- Every pill is the accent; only `ssh_<host>` sessions are tinted, from the `@thm_ssh_tints` cycle. Each entry carries its own ink (`bg:ink`) because Latte's accents span luminances — white is legible on mauve and illegible on yellow.
- Nothing on the bar uses `#()`. `status-right` reads session-scoped `@pill` / `@pill_ink` and escaped `session_name` directly in each client's target session, so two clients can show different correct pills without global derived state. The left mode pill is red whenever the prefix is held and blue for every other displayed mode. Window tabs append one authoritative `@walert`: red `!` bell, yellow `◆` silence, or green `●` activity, with bell > silence > activity. Window-tab icons are a nested `#{?#{==:…}}` chain (`@wicon`), keyed off `#{pane_current_command}`. `pane-border-format` reuses the same option and, because it is evaluated per pane, adds that pane's command plus a 20-character-truncated cwd basename (`remote` for `ssh`); the active label is blue/bold, while a dead label reports exit status and `prefix + R`. A `#()` re-runs on the **`status-interval` timer**, not on every redraw (measured: 6 windows at `status-interval 5` = 6 forks per tick; ordinary redraws reuse the cache; `refresh-client -S` bypasses it). Since this config sets `status-interval 0`, a `#()` would run once and then be **stale forever** — that, not fork cost, is why the bar has none, and why no status module can be added without turning the timer on and taking over `status-right`.
- Reboot persistence writes name, path and session-scoped `@layout`; `dev` rebuilds through `sessions/dev.conf`, while the old `agent editor git term` signature remains readable for migration. Client switching does not rewrite the roster. SSH sessions are listed but never auto-restored.
- Copy-mode search styles use yellow for ordinary matches, mauve for the current match, and red for the mark, all with computed inks. On tmux 3.6+ the compact position card and right-hand modal scrollbar appear only in copy/view mode; the scrollbar consumes one column and temporarily reflows the pane. Do not make it permanent or move these options outside the 3.6 guard.
- Work config is layered at the end of `tmux.conf` via `source-file -q` of `~/.config/tmux-work/work.conf` (private repo) and `~/.config/tmux/local.conf` (per-machine, gitignored).
- Neovim interplay: `Alt-hjkl` are `is_vim`-guarded so smart-splits keeps working; nvim's clipboard/focus rely on `set-clipboard on` and `focus-events on`. See README.

## Key conventions

- **English everywhere**: Conventional Commits (subject + body; the body explains the _why_), comments, README, this file.
- POSIX `sh` with `set -u`; keep `sh -n` clean. No bashisms **except** `shell/functions.sh`, which is sourced in zsh/bash and may use `local` and `${var//…}`.
- In `tmux.conf`, `|` is **not** a pipe — every pipe must live inside `run-shell '…'`.
- **Write hex in LOWERCASE.** Inside a `#{?…}` conditional, or inside an option pulled in with `#{E:…}`, tmux still honours the legacy one-letter shorthands, so `#FFFFFF` loses its `#F` to the window-flags shorthand and renders `*FFFFF` — but `#ffffff` does not, because there is no `#f` shorthand. Lowercase (which is how Catppuccin publishes its palette anyway) removes the whole bug class; the `##FFFFFF` escape it used to need is no longer necessary. Commas inside a conditional still need `#,`.
- **Never bundle a tmux flag that takes an argument**: `set-option -tu <name>` parses as `-t u`, silently targeting a session called `u`. Write `-u -t <name>`.
- Anything from a session name is untrusted in a format: escape `#` → `##` before it reaches the status bar.
- The bar and the popups need a **UTF-8 locale**; with `LC_CTYPE=POSIX` tmux silently drops the Nerd Font glyphs (found while testing on an isolated socket).
- Always brace shell vars around multibyte characters (`"${i}·${s}"`) — `/bin/sh` on macOS is bash 3.2 and would read `$i·` as one variable name and trip `set -u`.
- SSH invariants: never `set -g default-command`; sessions are named `ssh_<display-safe-host>` while exact `@ssh_host` metadata drives the shield; document the escape routes by which a pane could still reach a local shell (explicit command, `join-pane`/`move-pane`).
- Pane logs are `~/tmux-<safe-session>-w<window-index>-p<pane-id>.log`; session names must be reduced to a filename allowlist and the completed path shell-quoted before `pipe-pane` sees it.
- **A plugin may not own `default-command`, `status-interval` or `status-right`.** Those three are the SSH shield, the no-fork bar and the current-session pill. After adding or updating any plugin, assert on an isolated socket that `default-command` is still empty, `status-interval` is still `0`, and every `@thm_*` is still published. `tmux-sensible` fails the first (on macOS it runs `set -g default-command`), `catppuccin/tmux` fails the third (it opens with 37 `set -Ugq @thm_*`, unsetting the namespace `theme.sh` publishes), and every status module fails the second.
- **Check a plugin's key conflicts by key → COMMAND, never by which keys exist.** A plugin that steals a binding changes no key name, so a name-only diff reports nothing. `tmux-sessionist` silently replaced `prefix + C-Space` — the secondary leader — because its promote-window default `C-@` is the same keystroke as `C-Space`, and a name diff said "3 new keys, 0 lost". Diff `list-keys` output as `key<TAB>command` pairs against a run without the plugin.
- Plugin options do not reliably decline a binding: several plugins treat an empty option value as _unset_ and fall back to their default (`tmux-sessionist` does). Undo unwanted bindings after the load instead, and **rebind rather than unbind** anything that was already doing a job.
- The `ulimit` block only raises and caps at the hard limit (macOS soft `nofile` is 256, which crashes a multi-pane server).
- Keep the long explanatory comments, including the dead ends — they are why the config looks the way it does.
- Never push to `main` without the user verifying the phase on their Mac; develop on a branch.
